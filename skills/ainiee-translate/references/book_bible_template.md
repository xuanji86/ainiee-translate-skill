# BOOK_BIBLE 模板（译前事实抽取）

并行翻译前，派 1–2 个便宜 agent 通读各组源文（`work/par/grp_*_src.json`），按本模板产出
`<PROJ>/work/BOOK_BIBLE.md`。目的：**把「事实」在翻译前定死**——事实错了，风格再好也是错译，
而且往往是跨章一致的错（同一人全书衔级不对、同一亲属关系全书用错称谓），事后要改上百段。

只记**源文里能直接找到依据**的事实，附段号；推测另起一栏标「待确认」。不做翻译判断（那是词汇表与 STYLE_GUIDE 的事）。

## 5. 译法政策清单（审校开工前必须全部有答案）

Destiny 合集的教训：Jem'Hadar 保留英文还是译「詹哈达」、博格用「它」还是「他们」，都是 71 组审完才定，
只能再派一轮 agent 全书返工。凡是下面这类**全书性**的选择，审校（步骤 7.5）开工前一次问清，写进 EXAMPLES/红线/机械规则：

| 政策 | 候选 | 定为 | 依据/用户裁定日期 |
|---|---|---|---|
| 高频种族/势力名：音译还是保留英文（逐个列出，按出现次数排序） | | | |
| 集体/非人智慧体的代词（它 / 他们 / 他） | | | |
| 舰船代词（她 / 它） | | | |
| 军衔体系（Captain 舰长/上校分工、Admiral 实衔、外星军衔保留原文？） | | | |
| 人物说的外语短句（保留原文 / 译出 / 原文加注） | | | |
| 称谓（Doctor X → X 医生 / X 博士；Mister/Madam） | | | |
| 技术名词里的「新造词」（音译 / 意译 / 保留英文） | | | |

做法：`scan --mode all` + `review inventory` 跑全范围 → 把上表每行攒成选择题（附出现次数与 1–2 个例段号）一次问用户 →
答案落到 `EXAMPLES.md`、`config.json` 红线和项目的机械统一脚本；**机械能改的一律机械改，不交给审校 agent**。
